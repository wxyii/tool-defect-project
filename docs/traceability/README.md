## 编号和提取规则

- 提取包含“必须、不得、禁止、不能、只允许、至少、需要”等强制词的正文。
- 验收或检查清单章节中的每一项都视为强制要求。
- 跳过代码块、表头和 Markdown 分隔行。
- 编号由文档编号、章节路径和规范化要求文本的 SHA-256 派生，格式为
  `REQ-文档号-十二位摘要`。
- 行号仅用于定位，不参与编号；文本未改变时，移动行号不会改变编号。
- 要求文本发生语义修改时产生新编号，旧测试不会静默沿用。

## 映射语义

`mapping.json` 为每份设计文档配置计划任务和阶段门禁。每条要求还会得到：

- 任务自动化验证引用；
- 验收章节对应的人工验收引用；
- 涉及现场参数时对应 `Docs/decisions/` 中的稳定决策编号；
- 所有已发现测试的精确反向需求编号。

当前及后续 Python、Java、Kotlin、TypeScript 和 JavaScript 测试都会被扫描。
已有测试按文件职责映射，未知测试使用保守的架构原则兜底映射；新增模块应
及时增加更精确的规则，不能仅长期依赖兜底项。

## 只读验证

完整矩阵输出到标准输出，不改写设计文档：

```text
python tools/traceability/build_matrix.py
```

查看摘要：

```text
python tools/traceability/build_matrix.py --summary
```

验证冻结摘要、14 份设计文档覆盖、`DOC-16` 产品要求与 P0 验收覆盖、稳定编号、
任务门禁、现场/人工映射和所有测试反向链接：

```text
python tools/traceability/build_matrix.py \
  --verify-lock Docs/traceability/matrix-lock.json
```

`matrix-lock.json` 保存每份来源文档哈希、需求数量、需求编号摘要、`DOC-16`
产品要求摘要、验收摘要和完整稳定矩阵摘要。它不复制正文；完整逐条矩阵始终
由锁定工具从唯一来源确定性生成，避免维护第二份会漂移的规则文本。
