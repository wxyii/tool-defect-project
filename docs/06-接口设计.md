# 接口设计

## 1. 文档职责

本文定义网关后的 HTTP 接口、推理事件、幂等、并发和错误报文。Python 进程内插件接口见 [03-算法与预处理通用接口设计](03-算法与预处理通用接口设计.md)，数据库实现不在本文重复定义。

## 2. 接口分区

| 分区 | 前缀 | 调用方 | 鉴权 |
|---|---|---|---|
| 采集端接口 | `/api/v1/edge` | 工控机采集客户端 | 设备证书和客户端令牌 |
| 用户业务接口 | `/api/v1` | Vue 浏览器 | OIDC 用户令牌 |
| 内部服务接口 | `/internal/v1` | 推理、训练和发布服务 | 双向 TLS 和服务令牌 |
| 文件数据面 | `/objects` 或独立内部域名 | 采集端、后端、推理服务 | 短时签名或服务身份 |
| 健康与指标 | `/actuator`、`/health`、`/metrics` | 监控系统 | 仅管理网络可访问 |

Nginx 只做 TLS、路由、请求大小限制、限流和基础安全头，不实现业务状态机。

## 3. 通用约定

### 3.1 版本

- 对外路径使用主版本 `/v1`。
- 兼容新增字段不升级主版本。
- 删除字段、改变语义或改变状态机时升级主版本。
- 队列事件名携带版本，例如 `tool_defect.inference.task.v1`。
- JSON 请求的未知字段默认拒绝，响应新增字段要求客户端忽略。

### 3.2 时间和标识

- 时间使用 ISO 8601 UTC，例如 `2026-07-28T10:30:00.123Z`。
- 所有标识作为字符串传输。
- 金额不存在；概率使用 0 到 1 的 JSON 数字。
- 文件大小使用字节，时长字段名称带 `_ms` 或 `_seconds`。

### 3.3 请求头

| 请求头 | 用途 |
|---|---|
| `Authorization` | 用户或服务令牌 |
| `X-Request-Id` | 调用方可生成；缺失时网关生成 |
| `traceparent` | W3C 链路上下文 |
| `Idempotency-Key` | 创建、提交和发布等写操作的幂等键 |
| `If-Match` | 复核和配置更新的乐观锁版本 |

### 3.4 分页

列表接口使用游标分页：

```json
{
  "items": [],
  "next_cursor": "opaque-value",
  "has_more": false
}
```

游标是不透明字符串，客户端不得解析。导出大结果使用异步导出任务，不允许一次请求无限页长。

## 4. 采集端接口

### 4.1 创建设备采集事件

`POST /api/v1/edge/captures`

请求：

```json
{
  "capture_id": "019f...",
  "station_id": "019f...",
  "trigger": {
    "trigger_id": "plc-20260728-000123",
    "client_sequence": 123,
    "occurred_at": "2026-07-28T10:30:00.123Z",
    "source": "PLC"
  },
  "recipe_id": "019f...",
  "quality": {
    "status": "OK",
    "warnings": []
  },
  "images": [
    {
      "client_image_id": "camera-main",
      "image_role": "PRIMARY",
      "file_name": "capture.png",
      "media_type": "image/png",
      "size_bytes": 24581234,
      "sha256": "64位十六进制值",
      "width": 4096,
      "height": 4096
    }
  ]
}
```

响应：

```json
{
  "capture_id": "019f...",
  "status": "UPLOADING",
  "images": [
    {
      "image_id": "019f...",
      "upload": {
        "method": "PUT",
        "url": "https://storage.example/...",
        "headers": {
          "Content-Type": "image/png",
          "X-Checksum-Sha256": "..."
        },
        "expires_at": "2026-07-28T10:35:00Z"
      }
    }
  ]
}
```

幂等规则：

- `Idempotency-Key` 使用 `station_id:capture_id:create`。
- 相同键和相同请求摘要返回第一次结果。
- 相同键但摘要不同返回 `409 TD-API-CONFLICT-001` 并记录安全事件。

### 4.2 确认单张图片

`POST /api/v1/edge/captures/{capture_id}/images/{image_id}/complete`

请求再次携带 `size_bytes`、`sha256` 和对象上传回执。后端验证对象存在、大小和哈希后把图片置为 `AVAILABLE`。

重复确认同一内容返回成功；不同内容返回冲突，不允许覆盖。

### 4.3 提交检测

`POST /api/v1/edge/captures/{capture_id}/submit`

请求：

```json
{
  "requested_at": "2026-07-28T10:30:02Z"
}
```

响应状态为 `202 Accepted`：

```json
{
  "capture_id": "019f...",
  "status": "SUBMITTED",
  "detection_task_id": "019f...",
  "pipeline_version": "production-r8/12",
  "poll_after_ms": 500
}
```

后端只能从已批准的工位配置解析流水线，采集端不能任意指定生产模型。

### 4.4 查询结果

`GET /api/v1/edge/captures/{capture_id}`

```json
{
  "capture_id": "019f...",
  "capture_status": "REVIEW_PENDING",
  "detection": {
    "task_status": "SUCCEEDED",
    "algorithm_outcome": "UNQUALIFIED",
    "confidence": 0.9821,
    "model_version": "multitask/3"
  },
  "business_disposition": "HOLD",
  "review": {
    "status": "PENDING"
  },
  "poll_after_ms": 3000
}
```

采集端只使用 `business_disposition` 控制现场展示。

### 4.5 批量对账

`POST /api/v1/edge/sync/captures/query`

一次最多查询配置化数量的 `capture_id`，返回每项当前状态。该接口用于断网恢复，不接受客户端向中心写回状态。

### 4.6 心跳

`POST /api/v1/edge/devices/{device_id}/heartbeat`

上报代理版本、本地队列深度、最老任务年龄、磁盘使用率、相机状态、PLC 状态和时间偏差。心跳不替代业务任务上传。

## 5. 检测查询接口

### 5.1 列表

`GET /api/v1/detections`

支持按时间、产线、工位、最终处置、算法结论、复核状态、模型版本和错误码过滤。普通用户的范围由后端根据权限自动追加，不能相信前端传入的范围。

### 5.2 详情

`GET /api/v1/detections/{detection_task_id}`

返回：

- 采集元数据。
- 任务和各执行尝试。
- 标准化算法结果。
- 当前处置和处置历史。
- 图片元数据列表。
- 复核摘要。
- 模型、预处理和策略版本。

大图片只返回 `image_id`，不直接返回长期 URL。

### 5.3 图片访问授权

`POST /api/v1/images/{image_id}/access-ticket`

请求声明用途 `VIEW` 或 `DOWNLOAD`。后端做对象级权限检查并返回短时只读地址。普通查看默认禁止原始文件下载，只允许浏览器显示。

### 5.4 授权重试

`POST /api/v1/detections/{detection_task_id}/retry`

仅系统运维或被授权的质量负责人可用，必须给出原因。重试保留原任务并新增执行尝试；若要使用不同模型，应创建新的影子或重跑任务。

## 6. 人工复核接口

### 6.1 任务池

`GET /api/v1/review-tasks?status=PENDING&priority=P1`

后端按用户范围和角色过滤，返回缩略摘要，不在列表中签发全分辨率图片地址。

### 6.2 认领和释放

- `POST /api/v1/review-tasks/{review_task_id}/claim`
- `POST /api/v1/review-tasks/{review_task_id}/release`

认领响应包含 `lease_expires_at` 和 `record_version`。

### 6.3 提交

`POST /api/v1/review-tasks/{review_task_id}/submissions`

请求头：

```text
If-Match: "7"
Idempotency-Key: review_task_id:reviewer_id:client_submission_id
```

请求：

```json
{
  "decision": "FAIL",
  "reason_code": "MODEL_FALSE_NEGATIVE",
  "comment": "外缘存在明显缺口",
  "defect_type_codes": ["SPALLING"],
  "annotation_image_id": "019f...",
  "client_submitted_at": "2026-07-28T10:40:00Z"
}
```

版本冲突返回 `409`，响应包含当前任务版本和最新状态，但不自动覆盖。

### 6.4 人工掩膜上传

先调用 `POST /api/v1/review-tasks/{id}/annotation-upload-ticket`，上传完成后确认图片，再在提交中引用 `annotation_image_id`。掩膜必须是原图尺寸、单通道无损 PNG。

## 7. 数据集、训练和模型接口

这些接口只负责业务审批与查看，不直接在 HTTP 请求中执行长时间训练。

| 方法与路径 | 用途 |
|---|---|
| `POST /api/v1/dataset-versions` | 从已批准候选清单创建不可变数据集构建任务 |
| `GET /api/v1/dataset-versions/{id}` | 查看样本、审计和构建报告 |
| `POST /api/v1/training-runs` | 创建离线训练任务 |
| `GET /api/v1/training-runs/{id}` | 查看运行、指标和制品 |
| `POST /api/v1/model-versions/{id}/validation-decisions` | 提交验证结论 |
| `POST /api/v1/model-deployments` | 创建灰度或正式部署申请 |
| `POST /api/v1/model-deployments/{id}/approvals` | 独立审批 |
| `POST /api/v1/model-deployments/{id}/rollback` | 回滚到已批准版本 |

创建训练和部署返回 `202`，进度通过查询或服务器发送事件获取。

## 8. 内部推理接口

### 8.1 提交执行开始

`POST /internal/v1/detection-tasks/{detection_task_id}/attempts`

使用队列 `message_id` 幂等创建 `attempt_id`，记录工作进程和运行时。

### 8.2 提交结果

`PUT /internal/v1/detection-attempts/{attempt_id}/result`

请求体采用 [03-算法与预处理通用接口设计](03-算法与预处理通用接口设计.md) 的标准结果。使用 `PUT` 表示同一尝试只能有一个确定结果。

规则：

- 相同 `attempt_id + result_sha256` 重复提交返回 `200`。
- 同一 `attempt_id` 不同哈希返回 `409` 并报警。
- 派生对象必须先上传并确认。
- 后端成功写入后返回 `accepted: true`，工作进程方可确认队列消息。

### 8.3 提交失败

`PUT /internal/v1/detection-attempts/{attempt_id}/failure`

请求包含标准错误码、可重试建议、阶段和脱敏信息。最终是否重试由后端策略决定。

### 8.4 健康检查

- `/internal/v1/runtime/ready`：模型已加载并预热。
- `/internal/v1/runtime/models`：只返回已加载模型版本和哈希，不返回对象存储凭据。

## 9. 推理事件

交换机建议为 `tool-defect.inference`，路由键按环境和能力区分，例如：

```text
production.gpu.multitask
production.cpu.polar
shadow.gpu.multitask
```

事件：

```json
{
  "event_type": "tool_defect.inference.task.v1",
  "message_id": "019f...",
  "occurred_at": "2026-07-28T10:30:02Z",
  "traceparent": "00-...",
  "detection_task_id": "019f...",
  "capture_id": "019f...",
  "pipeline": {
    "pipeline_id": "019f...",
    "version": "12",
    "config_sha256": "..."
  },
  "images": [
    {
      "image_id": "019f...",
      "object_key": "raw/...",
      "sha256": "...",
      "media_type": "image/png"
    }
  ],
  "deadline_at": "2026-07-28T10:30:10Z"
}
```

队列约束：

- 持久化消息和持久化队列。
- 发布者确认。
- 消费者手动确认。
- 队列按任务类型隔离，避免 CPU 任务阻塞 GPU 任务。
- 死信消息进入专用死信队列，不能自动回原队列形成无限循环。
- `message_id` 和 `detection_task_id` 均做幂等。

## 10. 实时更新

浏览器采用服务器发送事件：

`GET /api/v1/events/stream`

事件只包含用户有权查看的资源摘要。断线后使用 `Last-Event-ID` 补取有限窗口；超出窗口则重新查询列表。采集端仍使用轮询和批量对账，不依赖长连接。

## 11. 错误报文

```json
{
  "code": "TD-STORAGE-CHECKSUM-001",
  "message": "图片校验失败，请重新上传",
  "request_id": "019f...",
  "trace_id": "32位值",
  "retryable": true,
  "details": [
    {
      "field": "sha256",
      "reason": "MISMATCH"
    }
  ]
}
```

约束：

- `message` 可面向用户，不能包含堆栈、绝对路径、SQL 或密钥。
- `code` 稳定，前端按错误码处理，不解析文案。
- `retryable` 是服务端建议，不代表客户端可无限重试。
- 参数错误使用 `400`，认证 `401`，无权 `403`，不存在 `404`，并发或幂等冲突 `409`，校验语义错误 `422`，限流 `429`，临时服务异常 `503`。

## 12. 请求限制

- JSON 元数据请求限制为小体量配置值。
- 图片禁止以 Base64 放入 JSON。
- 文件类型、像素尺寸、文件大小和解码后尺寸都要校验，防止压缩炸弹。
- 上传地址仅允许指定对象键、内容类型、大小和校验和。
- 查询接口限制时间范围和最大页长。
- 导出、训练和批量重跑采用异步任务。

## 13. 契约管理

1. HTTP 以 OpenAPI 3.1 文件为源。
2. RabbitMQ 事件以 AsyncAPI 或 JSON Schema 为源。
3. Java、TypeScript 和 Python 客户端从契约生成基础类型。
4. 持续集成执行向后兼容检查和消费者契约测试。
5. 文档示例必须通过模式校验，禁止手工维护三套不同字段。
