# P5 联合恢复演练报告

报告时间：2026-07-30

演练环境：隔离临时目录

演练状态：自动化联合恢复通过；生产恢复未执行

## 恢复点范围

恢复点模式 `tool-defect-recovery/v1` 强制同时包含：

1. 数据库业务记录；
2. 对象及其 SHA-256；
3. 当前不可变模型；
4. 数据集清单；
5. 审批证据；
6. 人工复核链。

清单同时保存业务记录、对象、审批和复核控制总数，以及跨六类组件的引用闭包。任一组件为空、当前模型不在模型组件、控制总数不一致、路径越界、符号链接、文件缺失或摘要冲突都会阻断恢复。

## 演练步骤与证据

自动化测试在临时源目录创建六类最小不可变制品，生成统一恢复点，验证源摘要，再复制到空的隔离目标。复制完成后对所有文件重新计算 SHA-256，并重新对账对象数量、当前模型、审批和复核控制总数。

正向演练结果：

- 恢复点文件数：6；
- 六类必需组件：完整；
- 引用闭包：完整；
- 源恢复点：`VERIFIED`；
- 隔离恢复：`RESTORED_AND_VERIFIED`；
- 备份成功是否被当作恢复成功：否。

负向演练结果：

- 篡改对象内容后摘要检查明确失败；
- 非空恢复目标明确拒绝；
- 缺失引用、组件或控制总数会明确失败；
- 工具不提供删除生产数据的路径。

验证命令：

```text
make test-faults
```

## 限制

本次是代码仓库内的隔离联合恢复演练，用于证明恢复点结构、完整性检查和对账逻辑可执行。它没有连接真实生产数据库、对象存储、设备或生产模型，也不替代 P7 的生产数据迁移、真实恢复时间记录和人员应急演练。
