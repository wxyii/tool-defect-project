# 管理员操作手册

## 角色边界

管理员是唯一的人员业务管理角色，拥有生产员工能力以及用户、样本、模型和受控配置管理能力；设备身份和服务身份不属于人员角色。管理员不得绕过资源状态、不可篡改、双人审批和审计约束。

## 正常操作

1. 根据已批准工单授予权限并设置有效期；系统管理员权限变更仍需完整记录。
2. 定期复核离职、调岗、禁用账号和角色冲突。
3. 验证权限拒绝、证书吊销和紧急账号自动回收。

## 两类角色与迁移

- 用户管理页面只允许 `PRODUCTION_EMPLOYEE`（生产员工）和 `ADMINISTRATOR`（管理员）。旧角色代码只作为历史迁移证据读取，不得重新授予旧权限。
- 先打开角色迁移预览，核对账号、禁用状态、旧角色快照和建议角色；逐账号填写确认原因后提交。旧复核、质量、算法、模型、安全、审计和系统管理角色不得自动提升为管理员。
- 显示 `CONFLICT` 或 `UNCONFIRMED` 的账号在确认前不得获得第二版人员权限；确认成功后旧会话会被撤销，账号必须重新登录。
- 同一账号重复提交相同角色是幂等操作；目标角色与既有决定冲突时停止操作并升级，不得覆盖历史决定。

## 用户管理顺序

1. 使用独立管理员账号核对并确认角色迁移。
2. 创建或编辑用户时只选择两类角色，并保存显示名称、状态和审计原因。
3. 停用、重置密码或变更角色后确认活动会话已失效；通知用户重新登录。
4. 高风险模型启用、回退、样本导出和策略变更必须由不同管理员审批，申请人与审批人不得为同一账号。

## 高风险控制

- 所需权限：人员管理、业务处置和模型发布权限；高风险操作必须使用独立确认人。
- 操作原因：提权、紧急账号、证书吊销和凭据轮换必须填写原因。
- 二次确认：安全负责人或运维负责人以不同账号确认高风险动作。
- 审计事件：申请人、执行人、确认人、前后权限、时限和结果完整记录。

## 安全失败

工单、确认人、有效期或审计写入失败时拒绝权限变更；身份提供方状态未知时不扩大权限，紧急账号保持禁用，业务状态保持 `HOLD`。
