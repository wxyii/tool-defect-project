# 数据库不可写

严重级别：S1

## 影响确认

- 确认主库写入探针、连接池、磁盘、复制和事务错误；停止形成需要数据库确认的新业务事实。
- 读取成功不代表可写；写入状态未知时所有待处置任务保持 `HOLD`。

## 只读检查

- 查看数据库健康、只读标志、磁盘与事务日志空间、连接数、最近迁移版本和恢复点。
- 核对发件箱与收件箱积压，不手工修改状态或重放事务。

## 恢复步骤

1. 修复容量、主从角色或数据库服务，保持应用有界重试。
2. 运行最小写入与回滚探针，确认迁移版本兼容。
3. 恢复消费后对账业务记录、发件箱、收件箱、对象引用和审计链。

## 升级路径

- 预计恢复超过恢复时间目标、发现数据损坏或需要切换恢复点时，立即升级数据库负责人和事件指挥。

## 恢复验证

- 新事务可提交、只读查询与控制总数一致、积压下降、没有重复业务结果。
- 任何哈希、迁移或恢复点不确定时继续 `HOLD`。

## 危险操作控制

- 所需权限：数据库恢复；操作原因：批准的事件工单；二次确认：数据库负责人和业务负责人；审计事件：`database.recovery.executed`。
- 禁止在未完成隔离恢复验证前覆盖生产数据库。
