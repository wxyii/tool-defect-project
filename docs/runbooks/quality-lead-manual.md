# 质量负责人手册

## 角色边界与高风险控制

- 所需权限：质量调查、数据集质量批准和模型质量批准；不得登记模型、执行发布、管理账号或修改审计事实。
- 操作原因：阈值、数据集、模型、推翻和回滚批准都必须记录具体原因。
- 二次确认：生产阈值和回滚需由工艺或发布负责人以不同账号确认。
- 审计事件：查询、导出、批准、拒绝、阈值变更和应急确认均形成追加写记录。

分母、证据、审批角色或模型身份未知时结论为 `HOLD`/拒绝，不得批准上线。

受众：质量负责人。权限：二审、升级裁决、批准标签和质量门槛。禁止：单人完成模型技术发布。

## 1. 质量看板

### 1.1 看板入口

登录后进入 `/quality` 页面，质量看板展示以下核心指标：

### 1.2 关键指标解释

| 指标 | 含义 | 关注阈值 |
|------|------|----------|
| 自动 PASS 率 | 自动判定为合格的比例 | 骤变 >10% 需调查 |
| 自动 FAIL 率 | 自动判定为不合格的比例 | 骤变 >5% 需调查 |
| HOLD 率 | 进入待定状态的比例 | >15% 需分析原因分布 |
| 复核通过率 | 人工复核确认自动判定的比例 | <85% 需评估模型性能 |
| 复核推翻率 | 人工复核推翻自动判定的比例 | >10% 需分析纠正模式 |
| 平均复核时长 | 从认领到提交的平均时间 | 超过 SLA 一半时关注 |
| 复核积压量 | 待复核队列长度 | >30 需调度复核资源 |
| 升级任务量 | 升级至质量负责人的待处理数 | >5 需立即处理 |
| 抽检合格率 | 抽检复核结论的通过率 | <90% 触发复核员培训 |
| 漏检率（估算） | 人工确认 PASS 后发现的缺陷 | 任何非零值需调查 |

### 1.3 趋势分析

- 按班次、产线、刀具型号筛选查看指标趋势。
- 关注指标在同一天内的周期波动。
- 对比模型版本变更前后的指标变化。
- 切换数据集版本前后至少保留 3 个班次的对比窗口。

### 1.4 告警

- 自动 FAIL 率超过 20% 且持续 1 小时：可能刀具批量异常或模型漂移。
- HOLD 率超过 15% 且持续 30 分钟：可能图像采集异常或推理服务降级。
- 复核积压超过 50 且增长趋势：安排临时复核人力。
- 升级任务超过 10 未处理：立即处理以防止产线停顿。

## 2. 数据集审批

### 2.1 审批前检查

1. 数据集版本号、创建人和创建时间确认无误。
2. 数据集所包含的样本来源可追溯：每条记录附 capture_id、原始图像摘要和复核 mask 摘要。
3. 标签分布合理：合格与不合格样本比例不超过训练策略规定的上限。
4. 无重复样本或来源冲突（同一 capture 出现两次）。
5. 数据集附带最近一次基础评估结果（准确率、IoU 等基准）。
6. 所有样本附加的 mask 已通过至少一次复核确认。
7. 数据集草稿中无未提交复核或仍处于 HOLD 的样本。

### 2.2 审批操作

1. 在数据集详情页点击"批准"，填写审批意见。
2. 审批通过后数据集变为已发布，不可编辑。
3. 审批不通过时填写拒绝原因和修改建议，退回算法工程师。
4. 审批记录自动审计，记录审批人、时间、版本和意见。

### 2.3 禁止

- 未检查清单即批准。
- 允许包含 HOLD 状态样本的数据集发布。
- 批准训练样本标签分布严重偏离生产预期的数据集。

## 3. 模型验证审批

### 3.1 审批前所需证据

提出模型发布申请时必须附以下证据，质量负责人逐项检查：

1. 训练运行报告：包含所用数据集版本、训练时长、损失曲线、最终验证指标。
2. 基准评估结果：在约定的留出测试集上的准确率、精确率、召回率、F1 和 IoU。
3. 安全测试通过：模型包签名和清单校验通过，无未声明文件，框架版本在允许列表。
4. 固定样例一致性：一组固定生产图像样例的推理结果与上一版本对比。
5. 性能基线：推理延迟、内存占用和吞吐量在目标硬件的测量结果。
6. 退化检查：新模型在已知缺陷类型上的指标未低于上一版本。

### 3.2 审批操作

1. 在模型详情页查看所有必要证据是否齐全。
2. 批准：包括质量负责人和模型发布负责人双重审批。
3. 拒绝：填写拒绝原因和所需补充证据。
4. 灰度发布建议：首次上线建议先灰度为 10% 流量，观察 4 小时无异常后全量。

### 3.3 禁止

- 在证据不完整时批准。
- 质量负责人独自完成模型发布审批（必须与模型发布负责人分别审批）。
- 批准安全测试未通过的模型。

## 4. 推翻调查

### 4.1 启动条件

当以下情况发生时启动推翻调查：
- 质量负责人撤销了自动判定或复核结论。
- 盲审二审结论不一致，质量负责人做出裁决。
- 单个班次内复核推翻自动判定的比例超过 10%。

### 4.2 调查步骤

1. 锁定被推翻任务的所有关联记录（原始图像、模型输出、复核标注、推翻原因）。
2. 检查自动判定的置信度分数是否在阈值边界附近。
3. 检查原始图像质量是否满足检测标准。
4. 对比被推翻样本与正确判定样本的图像特征差异。
5. 判断是单纯人工判断差异还是模型系统性盲区。

### 4.3 调查结论

- 个体差异：记录为复核员培训案例。
- 模型盲区：标记为训练数据候选样本，提交算法工程师评估纳入训练。
- 标签错误：修正并记录原因，通知数据管理员。
- 阈值不当：发起处置阈值调整流程。

### 4.4 记录

每次推翻调查必须形成书面记录，包含：
- 调查时间、涉及的 capture_id、推翻前后的判定。
- 调查人、调查结论和依据。
- 采取的纠正措施及责任人。

## 5. 训练数据治理

### 5.1 入选条件

样本进入训练数据集必须满足：
- 原始图像来源合法且摘要可验证。
- 复核结论已确认（PASS/FAIL），非 HOLD 状态。
- 标注 mask 经过质量抽检通过。
- 图像质量满足检测标准。
- 样本覆盖需同时包含易例（模型容易判断的）和难例（模型容易判断错的）。

### 5.2 审批工作流

1. 算法工程师创建数据集草稿并提交审批申请。
2. 质量负责人按第 2 节清单审查数据集。
3. 批准后数据集不可编辑，创建不可变版本号。
4. 训练运行绑定已发布数据集版本。

### 5.3 管理原则

- 不得将未经复核确认的样本纳入训练集。
- 不得将 HOLD 状态样本纳入训练集。
- 长期不用的老旧数据集应标记为归档，不直接删除。
- 数据集版本与训练运行和模型版本形成可追溯链。

## 6. 处置阈值调整

### 6.1 调整流程

1. 提出阈值调整申请：说明当前阈值、拟调整值、调整依据。
2. 质量负责人审核：检查依据是否充分（需附历史数据和统计分析）。
3. 在测试环境应用新阈值并评估对已知样本的影响。
4. 质量负责人签署批准并在变更记录中登记。
5. 运维在指定窗口期应用配置变更。
6. 变更后至少连续观察 8 小时或一个完整班次。

### 6.2 文档要求

每次阈值调整必须记录：
- 调整日期、调整前后的阈值数值。
- 调整依据：统计证据、评估报告引用。
- 批准人和执行人。
- 变更后观察期的关键指标变化。

### 6.3 禁止

- 无统计证据支撑的阈值调整。
- 未经质量负责人审批的阈值修改。
- 为绕过 HOLD 而将阈值调整为极端值。

## 7. 质量试运行与验收

### 7.1 试运行定义

质量试运行是指在真实生产环境中使用限定范围的刀具进行的质量性能验证，试运行不替代正式生产判定。

### 7.2 有效试运行的要素

- 试运行覆盖所有工位和所有刀具型号。
- 试运行样本量达到约定的最低数量。
- 所有试运行结果为 HOLD 或经人工复核确认后不进入正式处置。
- 试运行阶段系统的自动判定结果与人工复核结果进行对比统计。
- 试运行期间无 S1 级别故障。

### 7.3 验收标准

- 试运行样本达到约定的数量和时间跨度。
- 自动判定与人工复核一致率不低于约定的最低标准。
- 无未解决的 S1 事件。
- 复核积压未超过 SLA 上限。
- 所有关键告警已配置并经过演练验证。
- 质量负责人签署质量试运行通过报告。
