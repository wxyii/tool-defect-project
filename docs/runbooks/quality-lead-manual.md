# 管理员质量与样本导出操作手册

> 本文件沿用历史文件名。第二版在线系统不再设置“质量负责人”人员角色；本手册中的操作由获得相应原子权限的管理员执行。

## 1. 职责和边界

管理员质量职责包括质量调查、管理员反馈、待整理样本纳入或排除、样本导出审计、处置阈值建议、模型验证证据检查和质量试运行签署。

管理员不得：

- 创建、冻结、批准或比较数据集版本。
- 创建、调度或查看内部训练任务、进度、日志和检查点。
- 通过样本导出自动触发数据集或训练任务。
- 为外部整理或训练环境签发业务数据库、消息队列、对象存储或生产运行凭据。
- 绕过隔离验证上传模型，或由同一账号申请并确认生产启用。
- 修改历史检测、人工反馈、管理员反馈或审计事实。

样本导出是在线样本闭环终点。导出后的整理、划分、训练、实验跟踪和离线评估属于系统边界外流程，其可用性不得影响检测、复核、样本导出、模型上传、验证和生产运行。

分母、来源权限、对象哈希、验证证据、模型身份或确认人未知时，必须保持 `HOLD`、拒绝导出或拒绝启用，不得推定成功。

## 2. 质量看板

### 2.1 入口和指标

管理员登录后进入 `/quality` 页面。核心指标包括：

| 指标 | 含义 | 关注条件 |
|---|---|---|
| 自动 `PASS` 率 | 自动处置为合格的比例 | 相同口径骤变超过约定阈值时调查 |
| 自动 `FAIL` 率 | 自动处置为不合格的比例 | 相同口径骤变超过约定阈值时调查 |
| `HOLD` 率 | 等待人工或异常处理的比例 | 持续升高时分析原因分布 |
| 人工确认率 | 人工反馈与系统结论一致的比例 | 低于质量门槛时调查 |
| 人工推翻率 | 人工反馈与系统结论不一致的比例 | 高于质量门槛时调查 |
| 漏检数量 | 人工确认存在缺陷而系统未检出的数量 | 任一确认漏检都必须调查 |
| 待处理反馈量 | 等待管理员标记的图片项数量 | 超过服务时限时分配管理员处理 |
| 待整理样本量 | 尚未纳入或排除的候选数量 | 超过积压阈值时处理 |
| 样本导出失败率 | 导出作业中失败或部分失败比例 | 任一哈希错误立即调查 |
| 模型验证拒绝数 | 外部模型包未通过隔离验证的数量 | 按拒绝原因分类处理 |

所有比率必须显示分母、时间窗口、来源范围、模型版本和真值覆盖情况。没有足够人工确认时，不得把系统结论比例描述为真实缺陷率。

### 2.2 趋势分析

- 按来源、工位、班次、批次、使用阶段和模型版本筛选。
- 关注同一口径在日内和班次间的周期变化。
- 模型切换前后至少保留约定观察窗口，并使用实际执行模型版本分组。
- 样本候选和导出指标只反映在线整理过程，不显示数据集版本或训练指标。

### 2.3 告警

- `FAIL`、`HOLD` 或人工推翻率持续超过版本化阈值时启动质量调查。
- 待处理反馈或待整理样本超过服务时限时安排管理员处理。
- 导出对象缺失、哈希冲突、失败清单缺失或下载票据异常时停止交付。
- 模型包安全扫描、哈希、输入输出或固定样例失败时保持隔离。
- 外部训练环境不可用不是在线告警，不得据此将检测系统标记为故障。

## 3. 管理员反馈与推翻调查

### 3.1 启动条件

以下情况需要调查：

- 生产员工选择“确认存在缺陷”“确认无缺陷”或“无法判断”后，与系统结论不一致。
- 管理员复查发现误报、漏检、定位不准、图片不可用或暂无法确认。
- 同一来源范围内人工推翻率持续超过质量门槛。
- 图片质量异常、技术失败或处置为 `HOLD` 的数量异常增长。

### 3.2 调查步骤

1. 锁定图片项及其原图、派生图、逐图质量结果、系统结论、人工反馈和实际模型版本。
2. 检查原图和派生对象的大小、媒体类型和 SHA-256。
3. 检查系统置信度、质量边界、错误码和处置规则版本。
4. 对比相同来源和相同模型版本的正确与争议图片项。
5. 选择正确检出、误报、漏检、定位不准、图片不可用或暂无法确认。
6. 填写原因和影响范围并提交；系统必须创建不可变管理员反馈。

修改已提交结论时必须创建修订并关联被替代记录，不能覆盖原记录。“暂无法确认”必须保持待处理或 `HOLD`。

### 3.3 调查结论

- 人工操作差异：记录培训或操作改进，不改写历史反馈。
- 采集或图片质量问题：转设备或工艺调查，并按需加入待整理样本。
- 系统性误报、漏检或定位问题：加入待整理样本，等待纳入、排除或修订。
- 标签或标注争议：保持待处理，明确责任人和再次确认条件。
- 阈值不当：进入受控阈值调整流程。

“加入待整理样本”不等于加入数据集或触发训练。

## 4. 待整理样本管理

### 4.1 候选入口

进入 `/samples`，按管理员标记、候选状态、来源、使用阶段、模型版本和时间筛选。每个候选必须展示：

- 来源批次和图片项。
- 原图、结果图和对象哈希。
- 逐图质量结果和系统结论。
- 生产员工反馈及其修订链。
- 管理员反馈及其修订链。
- 检测时间、使用阶段和实际模型版本。

信息不完整时不得纳入可导出范围。

### 4.2 纳入

1. 确认候选关联的是指定管理员反馈版本。
2. 确认原图来源权限和允许用途。
3. 核对对象存在性、大小、媒体类型和 SHA-256。
4. 核对人工结论、管理员标记和可选标注坐标。
5. 填写纳入原因并提交。

同一图片项与同一反馈版本重复加入或重复纳入必须幂等。纳入决定只表示允许进入样本导出筛选，不创建在线数据集。

### 4.3 排除

出现以下任一情况时排除或保持待处理：

- 来源权限、用途或脱敏状态不明确。
- 原图缺失、损坏、哈希冲突或对象状态未知。
- 标签、管理员标记或标注坐标仍有争议。
- 图片与目标任务无关或内容重复且没有保留理由。
- 技术失败被误当作已确认质量标签。

排除必须填写原因。排除不删除图片项、反馈或候选，也不影响生产处置。

### 4.4 修订

候选决定、标注或原因需要调整时创建新修订，保存被替代决定、操作人、时间和变更说明。已被导出作业快照引用的旧版本继续可追溯，不能随当前修订变化。

## 5. 样本导出与审计

### 5.1 创建前检查

1. 筛选条件、候选数量和数据范围正确。
2. 所有候选均为当前允许导出的决定版本。
3. 原图、派生图和可选标注对象可读取且哈希一致。
4. 来源权限、用途、保留期和脱敏要求已确认。
5. 导出模式版本和目标用途已填写。
6. 大批量导出已指定不同管理员确认。

### 5.2 创建导出

1. 在 `/samples` 选择候选并查看完整范围预览。
2. 填写导出原因、用途和接收责任人。
3. 提交后核对筛选快照、候选决定版本和作业标识。
4. 等待服务端异步处理；不得通过反复点击创建重复作业。
5. 作业成功后核对清单数量、包哈希和失败清单。
6. 申请短时下载票据，并通过批准的人工渠道交接。

下载票据不得转发给无权限人员，不得写入邮件正文、工单评论或脚本配置。外部使用方不得获得在线对象存储长期凭据。

### 5.3 失败处理

- 任一必需对象失败时不得把作业报告为完整成功。
- 部分失败必须逐项查看失败清单，并按策略决定重新导出完整范围或允许完整子集。
- 对象哈希不符、清单缺失或状态未知时停止下载和交接。
- 重试使用原作业或明确的重试关系，不复制出不可追踪包。

### 5.4 审计核对

每次导出至少核对以下审计记录：

- 申请人、确认人、筛选快照和候选决定版本。
- 创建、执行、成功、部分失败或失败状态变化。
- 包对象引用、文件数、清单哈希和包哈希。
- 下载票据申请、签发、实际下载和到期。
- 接收责任人和外部用途说明。

导出完成是在线闭环终点。系统不得自动创建数据集版本、训练运行、训练任务或训练事件，也不得轮询外部使用状态。

## 6. 外部模型包验证证据检查

管理员从 `/models` 检查外部模型包，不要求内部数据集版本或训练运行。

### 6.1 必需证据

1. 模型名称、语义版本、上传人、上传时间和外部来源说明。
2. 包清单、逐文件 SHA-256、整体大小和声明哈希。
3. 输入尺寸、通道、归一化、输出名称和类别映射。
4. 框架、运行时、允许插件版本和许可证信息。
5. 外部评估摘要、测试范围、指标分母和已知限制。
6. 隔离环境中的路径安全、安全扫描、哈希、加载和资源上限结果。
7. 固定生产样例的推理、预热、时延和与当前模型的对比证据。
8. 已验证回滚目标和灰度观察方案。

外部来源可以附数据说明和训练说明，但它们只是审计附件，不能形成内部数据集或训练任务状态。

### 6.2 检查操作

1. 确认模型包由管理员通过浏览器直接上传到隔离区，而不是复制到生产目录。
2. 确认服务端已核对对象大小、媒体类型和 SHA-256。
3. 逐项查看隔离验证证据，状态未知或证据缺失时拒绝启用。
4. 对照当前模型检查固定样例、关键缺陷类型、推理时延和资源使用。
5. 发起启用申请时明确范围、观察窗口和回滚目标。
6. 由与申请人不同的管理员确认，随后执行加载、预热和原子切换。

### 6.3 禁止

- 把“上传完成”当作“验证通过”。
- 因缺少内部数据集版本或训练运行而补造记录。
- 接受哈希、签名、输入输出或许可证状态未知的模型包。
- 绕过固定样例、资源上限或隔离安全检查。
- 由同一管理员账号申请并确认生产启用或正式回滚。
- 让外部训练环境直接调用模型启用接口。

## 7. 处置阈值调整

### 7.1 调整流程

1. 提交当前值、拟调整值、依据、影响范围和回滚条件。
2. 检查统计分母、时间范围、模型版本和人工确认覆盖。
3. 在测试或影子范围评估对固定样例和历史记录的影响。
4. 由授权管理员提交变更申请，不同管理员确认高风险变更。
5. 在指定窗口生效并记录配置版本。
6. 至少观察一个约定窗口，异常时按回滚条件恢复。

### 7.2 禁止

- 无统计证据支撑的调整。
- 为绕过 `HOLD` 而使用极端阈值。
- 由前端直接计算或覆盖最终处置规则。
- 用外部训练进度或训练指标替代线上质量证据。

## 8. 质量试运行与验收

### 8.1 有效试运行

- 覆盖约定的来源、工位、刀具型号、使用阶段和模型版本。
- 达到约定的最低样本量和观察时间。
- 试运行结果不直接替代正式生产处置；需要时保持 `HOLD` 或完成人工确认。
- 系统结论与人工反馈采用相同口径进行统计。
- 期间没有未关闭的一级事件。

### 8.2 验收

- 试运行范围、分母和时间跨度达到约定值。
- 系统与人工结论一致性达到版本化门槛。
- 没有未解决的一级事件或超时积压。
- 样本候选、导出和模型验证告警已配置并演练。
- 当前生产模型、回滚目标和历史任务模型关联一致。
- 检测、复核、样本导出和模型管理在外部训练完全不可用时仍正常运行。
- 授权管理员签署质量试运行报告，相关组织责任人完成线下签署。

## 9. 安全失败和应急

- 来源权限、对象状态、哈希或候选决定未知：停止导出。
- 导出包清单或失败清单不完整：不得交接。
- 模型包身份、哈希、输入输出或验证状态未知：保持隔离。
- 启用确认人不独立或回滚目标未验证：保持当前生产模型。
- 外部训练不可用：记录外部事项，不影响在线服务状态。
- 在线系统出现数据集或训练写入口、菜单、权限、事件或服务依赖：视为范围回归，阻止第二版上线。
