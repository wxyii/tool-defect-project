# 联合备份与隔离恢复

严重级别：S1

## 影响确认

- 明确恢复点标识、数据库、对象、模型、数据集、审批和复核六类组件以及恢复时间目标。
- 备份任务成功不等于恢复成功；未完成隔离恢复与对账时生产恢复状态为 `HOLD`。

## 只读检查

- 验证恢复清单模式、创建时间、逐文件大小与 SHA-256、当前模型和引用闭包。
- 核对业务记录、对象、审批和复核控制总数，确认恢复目标为空且与生产隔离。

## 恢复步骤

1. 先在空隔离目录执行联合恢复，禁止覆盖已有目录。
2. 恢复后重新计算全部文件摘要，并对账业务记录、对象数量、当前模型、审批与复核链。
3. 记录实际耗时、遗漏和修订；只有审批后才能规划生产切换。

## 升级路径

- 任一组件缺失、摘要不符、当前模型不在闭包或控制总数不一致时停止并升级 S1 事件指挥。

## 恢复验证

- 恢复报告必须为 `RESTORED_AND_VERIFIED`，隔离标志为真，且明确没有把备份成功当作恢复成功。
- 任一引用未知时继续 `HOLD`。

## 危险操作控制

- 所需权限：恢复操作；操作原因：批准的恢复点与事件工单；二次确认：数据库、存储和业务三方；审计事件：`recovery.point.restored`。
- 禁止直接恢复到非空生产目录或忽略摘要差异。
