# 死信与重试耗尽

严重级别：S2

## 影响确认

- 确认死信数量、首末时间、稳定错误码、消息类型、源事件和是否持续增长。
- 哈希冲突、契约不兼容和不可恢复错误禁止自动回灌，业务结果保持 `HOLD`。

## 只读检查

- 查看发件箱 `DEAD` 记录、可靠性问题指纹、原始追踪、尝试次数和最后错误。
- 核对消费者版本、契约版本与依赖健康，不读取或复制消息中的敏感载荷。

## 恢复步骤

1. 先修复根因并用一条隔离消息验证。
2. 可恢复消息由授权人员选择问题指纹，填写原因后创建人工重试动作。
3. 每批观察失败率和积压；再次失败立即停止批次并保留原始死信事实。

## 升级路径

- 死信持续增长、涉及多个消息类型或不可确定幂等边界时升级事件指挥与契约所有者。

## 恢复验证

- 对账原始事件、人工动作、新投递和最终事实，确认没有覆盖历史或产生重复结果。
- 不能证明幂等时继续 `HOLD`。

## 危险操作控制

- 所需权限：`reliability:retry`；操作原因：非空工单原因；二次确认：值班负责人；审计事件：`reliability.issue.actioned`。
- 禁止直接改写消息载荷、删除死信或把不可恢复错误改成可重试。
