# ADR-0007：模型直接上传安全边界

- 状态：已接受
- 日期：2026-08-03
- 决策版本：`1.0.0`
- 需求基线：`DOC-16 1.1.1`
- 影响契约：第二版目标契约 `2.0.0`
- 影响阶段：`R0`、`R1`、`R2`、`R8`、`R9`

## 背景

管理员需要从网页接入外部模型包。模型包属于不可信供应链输入，上传成功不代表可加载或可生产启用；业务后端也不适合代理大文件。

## 决策

业务后端只创建上传会话并签发短时、单对象、限大小和限类型的授权。浏览器把模型包直接写入隔离对象前缀。服务端确认实际大小与 SHA-256 后，验证作业在无业务凭据、无任意网络权限和受资源限制的环境中完成安全解包、文件清单、签名与物料清单、白名单、恶意内容、模型加载、输入输出和固定样例检查。

验证失败的对象保持隔离并记录脱敏原因，不登记为可启用版本。只有形成不可变验证证据、准备已验证回退目标并经不同管理员确认后，才允许原子切换每组织唯一生产默认模型。样本导出和模型上传是独立入口，不得通过内部数据集或训练任务串联。

## 替代方案

1. 把模型二进制经业务接口上传：拒绝，因为扩大内存、超时和凭据暴露风险。
2. 上传后由生产推理服务直接试载：拒绝，因为未验证包会进入生产信任域。
3. 以管理员身份或来源说明替代自动验证：拒绝，因为不能证明包结构、安全性和运行兼容性。

## 后果

- 需要隔离桶、专用验证身份、配额、超时、孤儿清理和不可变证据。
- 外部模型来源必须完整且与第一版内部历史来源互斥。
- 验证基础设施不可用时上传能力关闭，当前生产模型保持不变。

## 回滚条件

任一哈希、签名、扫描、加载、预热或审批前置不满足时停止切换并保持当前生产模型。新模型已切换后出现严重异常时，只能回退到重新验证和预热成功的历史版本；失败不得强制切换。
