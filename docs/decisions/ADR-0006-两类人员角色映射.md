# ADR-0006：两类人员角色映射

- 状态：已接受
- 日期：2026-08-03
- 决策版本：`1.0.0`
- 需求基线：`DOC-16 1.1.1`
- 影响契约：第二版目标契约 `2.0.0`
- 影响阶段：`R0`、`R2`、`R6`、`R9`

## 背景

目标人员业务角色只有生产员工和管理员，但第一版存在操作员、复核员、算法、质检负责人、审计员等角色。直接按旧角色名称自动映射会产生越权，且设备与服务身份不属于人员角色。

## 决策

第二版人员会话仅暴露 `PRODUCTION_EMPLOYEE` 和 `ADMINISTRATOR`。设备身份、服务身份以及后端内部原子权限继续独立存在。旧账号必须先生成影响预览和逐账号映射清单；未明确确认的旧高权限账号不得获得管理员权限。

角色切换时撤销旧会话。生产模型启用、正式回退和达到阈值的大批量样本导出仍要求不同管理员账号确认，管理员角色本身不能绕过职责分离。

## 替代方案

1. 将所有旧高权限角色自动合并为管理员：拒绝，因为违反最小权限和禁止自动提权。
2. 只在前端隐藏旧角色：拒绝，因为不能替代后端鉴权和会话撤销。
3. 把设备与服务身份映射为生产员工：拒绝，因为会混淆认证主体和审计责任。

## 后果

- 需要运行时用户清单、授权确认和旧会话撤销证据。
- 第二版菜单、路由和权限注册表不得出现数据集或训练人员能力。
- 旧角色在批准兼容窗口内只用于第一版读取与迁移，不得创建第二版管理授权。

## 回滚条件

发现未授权提权、数据范围扩大或旧会话仍有效时，立即关闭第二版人员入口并撤销新会话；保留映射清单和审计证据，不回写旧授权历史。

## 验收
