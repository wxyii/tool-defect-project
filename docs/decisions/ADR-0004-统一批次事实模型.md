# ADR-0004：统一批次事实模型

- 状态：已接受
- 日期：2026-08-03
- 决策版本：`1.0.0`
- 需求基线：`DOC-16 1.1.1`
- 影响契约：第二版目标契约 `2.0.0`
- 影响阶段：`R0`、`R1`—`R5`、`R9`

## 背景

系统需要同时承载产线采集和浏览器手工多图上传。若两种来源各自维护状态机、检测记录和历史查询，逐图失败隔离、批次计数、权限和审计会形成两套语义。

## 决策

两种来源统一写入“批次—图片项—检测任务—执行尝试”事实模型。手工上传形成多图片项批次；每个新产线触发形成一个包含单图片项的批次。第二版每个图片项只关联一张原图，批次状态只能由图片项事实重算。

来源差异只保留在来源类型、可选 `capture_id`、创建主体和使用阶段快照中，不允许改变图片项状态机、推理结果或最终处置规则。跨进程字段必须先进入第二版契约，再生成消费者类型。

## 替代方案

1. 维持产线与手工两套模型：拒绝，因为会复制状态、幂等、权限和历史规则。
2. 把整个手工批次视为一次推理任务：拒绝，因为单图失败会污染整批且无法独立重试。
3. 把产线触发直接写成无批次图片：拒绝，因为无法使用统一聚合和查询接口。

## 后果

- 数据库需先扩展、回填和影子读，再切换消费者。
- 批次提交为每个图片项建立独立逻辑任务，重试只新增执行尝试。
- 第一版产线适配在兼容期继续存在，历史记录不原地改写。

## 回滚条件

在第二版写入放量前可关闭相应功能开关并回到仍通过验证的第一版产线路径。已经写入的第二版事实不得删除或回写；影子读出现差异、计数不可重建或来源映射不确定时进入 `HOLD` 并停止切换。
