# ADR-0002：P2 采集端轻量传输与图片校验边界

- 状态：暂定默认值，生产启用前必须复审
- 日期：2026-07-29
- 负责人：采集与设备负责人
- 最迟复审门禁：G7
- 影响范围：`apps/edge-agent/`

## 背景

目标技术栈推荐 HTTPX 与 OpenCV。P2 只建设离线队列、模拟设备、契约同步
和安全失败基础；真实相机、PLC、现场操作系统与厂商软件开发包仍是上线阻断
决策。此时把算法环境或厂商运行时带入采集进程，会提前固化尚未确认的部署
约束。

## 暂定决策

- P2 控制面传输使用 Python 3.11 标准库实现，仅开放冻结 v1 中采集端需要
  的七个操作，并强制 HTTPS、Bearer、可注入 mTLS 上下文、超时、拒绝重定向、
  契约哈希一致性和响应边界校验。
- P2 图片完整性探测使用 Pillow 的完整像素流加载，只承担 PNG/JPEG
  可解码性、格式和尺寸校验，不承担算法预处理或厂商相机取流。
- 真实相机适配与任何图像算法仍按目标栈使用 OpenCV 或厂商软件开发包，
  必须在 P7 现场决策关闭后实现和验收。
- 若后续改用 HTTPX，只能替换传输适配层，不得改变生成客户端、幂等键、
  本地队列状态和错误语义。

## 安全边界

- 当前实现只允许模拟硬件，不构成生产设备批准。
- 网络测试必须通过可注入传输验证断网、超时、限流、服务不可用、身份失败
  和 mTLS 失败；签名地址、令牌与控制面回执不得进入错误文本。
- Pillow 只安装在独立采集环境，禁止把 TensorFlow、Matplotlib 等算法
  重依赖带入采集进程。
- G7 前必须用目标工控机、真实证书和对象存储重新验证；未完成时保持上线
  阻断，不能声称 HTTPX/OpenCV 生产基线已经验收。
