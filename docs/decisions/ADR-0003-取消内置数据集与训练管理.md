# ADR-0003：取消内置数据集版本与训练运行管理

- 状态：已接受
- 日期：2026-08-02
- 决策版本：`1.0.0`
- 需求基线：`DOC-16 1.1.0`
- 影响契约：第二版目标契约 `2.0.0`
- 影响阶段：`R0`、`R1`、`R2`、`R6`、`R7`、`R8`、`R9`

## 背景

原方案把生产反馈、数据集版本、内部训练运行和模型发布设计为同一在线闭环。最新产品边界要求在线系统只负责检测、人工反馈、待整理样本、可审计样本包导出，以及外部模型包的直接上传、隔离验证、启用和回退。数据集管理和训练执行由系统边界外的环境承担。

当前第一版实现中，模型登记仍可能要求 `dataset_version_id` 和 `training_run_id`，数据库也可能保留相关表、外键和历史记录。因此本决策同时规定目标能力和兼容退役方式，避免把取消功能改名后继续保留，也避免破坏历史证据。

## 决策

### 1. 在线业务终点

样本在线闭环以“样本导出包生成成功或明确失败”为终点。系统可以记录候选来源、纳入/排除决定、导出清单、对象哈希、失败项、下载审计和可选外部引用，但不得在导出后自动创建数据集版本或训练任务。

### 2. 明确取消的能力

第二版不得提供或生成以下能力：

- 数据集创建、冻结、批准和版本差异页面、菜单、人员权限、写接口或事件。
- 内部训练任务创建、调度、恢复、进度、日志、指标和检查点页面、菜单、人员权限、写接口或事件。
- 数据集构建、训练调度或实验跟踪工作进程作为在线部署单元。
- 在线业务对内部或外部训练平台的接口调用、消息事件、共享凭据或可用性依赖。

取消清单不能通过改名为“样本版本”“模型改进任务”等方式重新进入第二版。

### 3. 允许保留的能力

系统保留：

- 待整理样本候选的筛选、去重、冲突标记、纳入、排除和修订记录。
- 可审计样本导出作业、导出包、短时下载授权和下载审计。
- 管理员从浏览器直接上传外部模型包到隔离对象前缀。
- 模型包完整性、安全性、输入输出兼容性和固定样例验证。
- 不同管理员确认后的模型启用、灰度、回退和历史追踪。

“样本导出”和“模型直接上传”是两条独立支线。模型上传不得要求系统内存在样本导出、数据集版本或训练运行记录。

### 4. 外部训练边界

外部环境可以自行完成样本清洗、数据集组织、训练、实验跟踪和评估，但不属于本系统信任边界。外部环境不得持有业务数据库、生产对象存储、消息系统或在线服务凭据。交接只通过受控样本导出包和管理员上传的模型包完成；外部引用仅是可审计文本，不是在线外键，也不触发网络调用。

### 5. 第二版契约规则

第二版允许的替代资源包括 `SampleCandidate`、`SampleExportJob`、`SampleExportPackage`、`ModelUploadSession`、`ModelPackage`、`ModelValidation` 和 `ModelDeployment`。

第二版禁止出现 `DatasetVersion`、`DatasetApproval`、`DatasetDiff`、`TrainingRun`、`TrainingJob`、`TrainingLog`，以及 `dataset.create`、`dataset.approve`、`training.start` 等人员权限或同义写能力。模型登记模式不得把 `dataset_version_id` 或 `training_run_id` 定义为必填字段或在线外键前置条件。

这里禁止的是一等业务资源：第二版没有独立数据集/训练列表、详情路由、状态机、写接口或页面。为保证历史可追溯，模型历史和审计响应可以嵌入通用只读 `LegacyProvenanceSnapshot`，其内容限于来源类型、第一版标识、不可变摘要、归档引用、SHA-256 和保留时间；它不能独立查询、修改或触发任何在线任务。

### 6. 第一版兼容与数据保留

- 第一版契约、生成包、数据库表和历史记录在保留期内继续归档，不原地改写历史语义。
- 第一版数据集/训练写能力使用独立开关，先进入弃用期，再在消费者归零后提前返回 `410 / TD-LEGACY-FEATURE-RETIRED`；它不等待第一版产线采集接口下线，也不得无操作返回成功或把任务永久排队。
- “消费者归零”必须有机器可读清单、调用指标和批准观察窗口；遥测缺失不等于调用为零。
- 新数据库迁移只能把旧模型关联字段调整为兼容可空或迁移到外部来源说明，禁止修改已执行的历史迁移。
- 历史数据集和训练记录只读保留，不进入第二版状态机。第一版读取接口在归档窗口内保留，只有在引用历史已生成可验哈希的通用只读快照、模型历史和审计查询验证通过后才能关闭；破坏性删除必须另立决策并完成备份、引用检查和恢复演练。
- 内部数据集构建和训练工作进程不得进入第二版生产部署，也不得成为检测、复核、导出、模型验证或模型切换的前置条件。

模型来源必须满足互斥且完备的数据库约束：历史内部模型同时关联合法第一版数据集与训练记录；外部上传模型同时关联已确认上传会话与不可变外部来源快照。两种来源都为空、任一来源不完整或两种来源同时存在时拒绝登记或保持 `HOLD`。

## 影响

### 正向影响

- 缩小在线系统和人员权限面，减少训练依赖、供应链凭据和长任务状态管理。
- 模型来源可以是任意受控外部环境，不再被历史内部训练记录锁定。
- 样本导出仍保留来源、哈希和审计证据，便于外部改进和合规交接。

### 代价

- 系统不展示外部数据集状态、训练进度、日志和实验指标。
- 外部训练的可复现性由外部交付规范和模型包证据负责，不能由在线业务数据库代替。
- 第一版表和接口需要经过一段只读兼容期，不能一次性破坏性删除。

## 分阶段落地

1. `R0` 冻结取消清单、消费者清单和历史保留策略。
2. `R1` 在第二版契约中加入负向门禁，确保取消资源和事件无法生成。
3. `R2` 新增样本导出和模型上传持久化模型，建立互斥完整的模型来源约束，并在取消消费者归零后提前关闭第一版数据集/训练写入。
4. `R6` 删除页面、菜单、路由和人员权限。
5. `R7` 完成待整理样本和可审计导出，以导出为在线终态。
6. `R8` 完成独立的外部模型直接上传、隔离验证、启用和回退。
7. `R9` 删除已经停写的第一版实现、事件消费者和内部在线流水线触发器，并在通用历史快照验证后关闭遗留读取。

## 验收

- 第二版契约和三语言生成类型中不存在取消资源、写接口、事件和权限。
- 浏览器不存在数据集与训练菜单；旧路由不能进入隐藏页面。
- 生产员工和管理员的会话中均无数据集或训练运行权限。
- 样本导出成功后不产生数据集版本、训练运行或训练事件。
- 第一版取消写消费者清单完整、批准观察窗内调用为零，停写后返回 `410 / TD-LEGACY-FEATURE-RETIRED` 且不创建任务。
- 每个模型版本恰好满足一种完整来源；无来源、不完整来源和双重来源均被数据库拒绝。
- 在数据集构建与训练服务未部署的环境中，检测、复核、样本导出、模型上传、验证、启用和回退仍可通过。
- 第一版独立读取关闭后，模型历史和审计仍能通过通用只读快照核对旧标识、归档引用和哈希。
- 第一版退役接口明确失败，历史记录仍可只读追溯。
