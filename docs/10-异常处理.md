# 异常处理

## 1. 文档职责

本文定义错误分类、重试、补偿、降级、死信和人工处置。错误监控和告警阈值见 [11-日志与监控](11-日志与监控.md)。

## 2. 总体原则

1. 先判断错误是否可恢复，再决定重试。
2. 重试必须幂等并带退避和抖动。
3. 参数、权限、哈希冲突和模型不兼容不得自动重试。
4. 技术异常不得映射为 `PASS`。
5. 每次失败保留阶段、错误码和执行尝试。
6. 用户文案、运行日志和审计信息分层，不能把堆栈返回前端。
7. 到达重试上限后进入明确的死信或人工处置，不无限循环。

## 3. 错误码

格式：

```text
TD-{COMPONENT}-{CATEGORY}-{NNN}
```

组件示例：

- `EDGE`：采集客户端。
- `CAMERA`：相机。
- `PLC`：触发源。
- `API`：业务接口。
- `STORAGE`：图片或文件存储。
- `QUEUE`：消息队列。
- `PREPROCESS`：预处理。
- `MODEL`：模型加载。
- `INFER`：推理。
- `REVIEW`：人工复核。
- `SAMPLE_EXPORT`：样本整理与导出。
- `MODEL_UPLOAD`：模型直接上传和隔离验证。
- `REGISTRY`：模型登记和发布。
- `SECURITY`：鉴权、哈希和签名。

类别示例：

- `VALIDATION`：输入不合法。
- `TRANSIENT`：临时故障。
- `TIMEOUT`：超时。
- `CONFLICT`：幂等或并发冲突。
- `RESOURCE`：磁盘、内存、显存不足。
- `INCOMPATIBLE`：版本或协议不兼容。
- `INTEGRITY`：内容校验失败。
- `INTERNAL`：未预期缺陷。

错误码一经对外发布不改变语义。

## 4. 重试决策

| 错误 | 自动重试 | 处置 |
|---|---|---|
| 网络断开、连接超时、HTTP 503 | 是 | 指数退避并保留原任务 |
| HTTP 429 | 是 | 遵守 `Retry-After` |
| 图片大小或 SHA-256 不一致 | 先重传一次 | 仍失败则隔离并 `HOLD` |
| JSON 模式校验失败 | 否 | 修正客户端或配置 |
| 认证失败、证书过期 | 否 | 停止发送并告警 |
| 幂等键相同但请求内容不同 | 否 | 安全冲突，人工调查 |
| 相机暂时繁忙 | 有限重试 | 超过采集窗口则保存失败事件 |
| 相机无图、全黑或损坏 | 否或重新触发一次 | `HOLD`，保留证据 |
| 预处理无法定位刀具 | 通常否 | `INCONCLUSIVE` 并复核 |
| 模型文件缺失、哈希或签名错误 | 否 | 隔离模型，阻断部署 |
| GPU 显存不足 | 有限重试 | 释放模型或转兼容工作池 |
| 推理进程崩溃 | 是，有限次数 | 新增执行尝试 |
| 复核版本冲突 | 否 | 用户刷新后重新判断 |
| 样本候选内容或标签冲突 | 否 | 排除冲突候选或修订后重新导出 |
| 样本导出对象或清单哈希不一致 | 否 | 作业失败，隔离导出包并调查 |
| 外部模型包损坏、来源证据缺失或不兼容 | 否 | 保持隔离，拒绝登记和发布 |

## 5. 退避基线

### 5.1 采集端

中心网络异常时，按 1、5、30、120、600 秒退避，之后每 15 分钟重试并加入随机抖动。采集端没有固定的短重试上限，只要本地数据完整就持续补传；但持续失败必须产生运维告警。

上传授权过期时重新申请，不重用过期地址。

### 5.2 中心推理

建议默认最多 3 次执行尝试，间隔 30、120、600 秒。以下情况不消耗重试：

- 重复队列消息且结果已经接受。
- 工作进程在开始执行前发现任务已取消。

超过上限进入死信，采集事件保持 `HOLD`。

### 5.3 内部回调

结果已经写入对象存储但后端回调暂时失败时，保留本地小型结果清单并重试。后端以 `attempt_id + result_sha256` 幂等接受。不能重新推理来替代结果回调重试。

所有次数和间隔配置化，并由监控验证是否产生重试风暴。

## 6. 采集端异常

### 6.1 重复触发

- 以触发源序号和去抖窗口识别。
- 同一触发不得覆盖原图。
- 无法确定是否重复时，创建新的 `capture_id` 并标记关系，交中心去重分析。

### 6.2 触发序号跳变

保存前后序号、时间和设备状态，继续处理当前可确认触发，同时产生设备告警。

### 6.3 图片写入失败

- 临时文件未完成时不写入 `PENDING`。
- 磁盘不足时停止接受新采集并通知现场，不能把空文件作为成功。
- 启动时扫描临时文件，完整则恢复，不完整则隔离。

### 6.4 SQLite 异常

- 数据库忙按短退避重试。
- 完整性检查失败时停止自动清理，备份损坏文件并从目录清单重建新库。
- 重建只恢复同步事实，最终业务状态仍向中心对账。

## 7. 上传和存储异常

### 7.1 上传成功但确认失败

采集端重复调用确认。后端先查对象，不要求重新上传。

### 7.2 数据库成功但对象缺失

不允许图片进入 `AVAILABLE`。一致性扫描发现后把记录隔离、阻断检测并告警。

### 7.3 对象成功但数据库事务失败

对象保持暂存，由孤儿扫描器依据上传会话重新挂接或在审计窗口后清理。

### 7.4 哈希冲突

同一对象键出现不同 SHA-256 时：

1. 禁止覆盖。
2. 隔离新对象。
3. 返回非重试冲突。
4. 记录设备、账号和请求摘要。
5. 触发安全告警。

## 8. 队列异常

- 发布失败由事务发件箱重试。
- 消费者崩溃前未确认的消息可重新投递。
- 消费者先做业务幂等检查，再执行模型。
- 超过执行上限或明确不可恢复的消息进入死信队列。
- 死信队列不自动回灌，必须由有权限人员选择“重试原任务、创建新任务或关闭”。
- 队列积压时按任务优先级保护在线生产任务，暂停影子和批量任务。

## 9. 预处理与推理异常

### 9.1 输入问题

图片不可解码、尺寸超限或格式不支持，返回 `INPUT_INVALID`，业务处置为 `HOLD`。

### 9.2 定位失败

环形预处理找不到可靠内外边界时，保存可用的诊断中间量，返回 `PREPROCESS_REJECTED`，不继续用错误几何运行模型。

### 9.3 模型不兼容

输入形状、输出名、标签映射、框架版本、插件版本或制品哈希不匹配时：

- 运行槽不进入 `READY`。
- 任务不自动切换到未经批准的其他模型。
- 若存在该工位明确批准的回退版本，后端可创建新任务并记录回退原因。

### 9.4 资源耗尽

显存不足先排空工作进程并重启运行槽；同一模型连续发生时隔离该版本。CPU、内存或临时盘不足时暂停领取新任务。

### 9.5 结果不合法

概率越界、概率和不合理、掩膜尺寸错误、结果缺少版本或对象哈希时，视为插件错误，不入业务结果。

## 10. 复核异常

- 认领租约过期：保存未提交草稿，任务回池。
- 乐观锁冲突：返回当前版本，禁止覆盖。
- 掩膜上传成功但提交失败：保留暂存对象，允许重新提交；过期后由孤儿扫描清理。
- 二审人员与一审相同：后端拒绝。
- 原因码已停用：旧记录可查看，新提交拒绝并要求选择有效原因。
- 图片访问失败：不能在未看原图的情况下提交，记录服务故障。

## 11. 样本导出、模型上传与发布异常

### 11.1 样本整理和导出

以下问题必须使导出作业明确失败或部分失败，不得生成“完整成功”结果：

- 被纳入候选的原图、标注或来源记录缺失。
- 标签或来源冲突未解决。
- 清单、对象数量、大小或 SHA-256 无法对账。
- 样本来源没有导出授权。
- 短时下载票据越权、过期或被重复滥用。

单个对象失败时保留失败项和已经完成的对象证据，由管理员修订候选后创建新的导出作业。导出失败不得自动创建数据集或训练任务。

### 11.2 模型直接上传与隔离验证

- 上传声明与对象大小或 SHA-256 不一致：隔离对象，上传会话失败。
- 压缩包包含路径穿越、链接、设备文件、未声明文件或超限内容：拒绝解包和登记。
- 外部来源说明、软件物料清单、输入输出约定或评估证据缺失：保持 `HOLD`。
- 签名、框架、插件、模型加载、固定样例或预热检查失败：保持隔离，不影响当前生产模型。
- 验证进程崩溃或资源超限：有限重试独立验证作业；达到上限后明确失败，不能在生产推理进程继续验证。

外部训练平台的 NaN、调度、日志或检查点异常不属于本系统错误状态。系统不接收其回调或事件，也不因其不可用改变在线业务状态。

### 11.3 发布

模型下载、验签、加载或预热失败时不切流。灰度发生严重异常时自动或人工回滚到上一已验证版本，不能覆盖新模型制品。内部数据集或训练记录缺失不得成为外部模型包上传和验证错误。

## 12. 熔断和降级

- 对象存储不可用：后端停止创建可执行任务，采集端继续本地排队。
- RabbitMQ 不可用：业务任务和发件箱仍可提交，发布器恢复后补发。
- 推理服务不可用：队列积压，现场处置保持 `HOLD`。
- 复核系统不可用：自动满足规则的结果仍可定案；需要复核的保持 `HOLD`。
- 监控系统不可用：业务可短时继续，但必须产生独立的“监控失明”告警。

降级不能绕过鉴权、文件校验或人工复核要求。

## 13. 人工处置和运行手册

每类严重错误必须有运行手册，至少写明：

1. 如何确认影响范围。
2. 哪些数据可能丢失或重复。
3. 可安全执行的只读检查。
4. 恢复、重试、回灌或回滚步骤。
5. 何时需要现场暂停。
6. 何时升级给质量、算法、安全或基础设施负责人。
7. 如何验证恢复完成。

所有人工“忽略、关闭、回灌、重跑、回滚”操作都要求原因并进入审计。

## 14. 验收用例

- 模拟网络断开和恢复，不丢图、不重复建业务结果。
- 模拟对象上传后数据库回滚，孤儿对象可清理。
- 模拟重复队列消息，只有一个结果被接受。
- 模拟模型哈希错误，运行槽不就绪且不切流。
- 模拟 GPU 进程崩溃，任务有限重试后成功或进入死信。
- 模拟复核并发冲突，无后写覆盖。
- 模拟死信回灌，必须经过权限和原因检查。
- 模拟样本导出单项失败，作业不会宣称完整成功，也不会创建训练任务。
- 模拟恶意或不兼容模型包，隔离验证失败且当前生产模型不受影响。
- 模拟外部训练环境不可用，在线检测、样本导出和既有模型推理仍正常。
- 所有失败场景的业务处置均不是 `PASS`。
