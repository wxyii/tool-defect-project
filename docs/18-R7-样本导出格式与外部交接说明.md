# R7 样本导出格式与外部交接说明

**适用版本：** `v2 / 2.0.0`  
**导出格式：** `r7-sample-export/1`  
**适用范围：** 管理员从手工批量检测结果中整理样本，并将可审计样本包交给受控的外部人工处理方。

## 1. 范围和用途

R7 导出包用于人工整理、核对和受控交接。它不是数据集版本、训练运行、模型注册或任何自动训练任务的创建入口。导出请求只携带已纳入候选的标识、来源快照和筛选快照；后续是否用于其他系统，必须由有权限的人员按另一套批准流程处理。

导出功能默认关闭。对象存储、队列、版本证据或哈希校验任一前置条件不可用时，系统必须返回明确失败或 `HOLD`，不得将部分结果标记为完整成功。

## 2. 包内布局

```text
manifest.json
samples/{sample_candidate_id}/original.png
samples/{sample_candidate_id}/original.jpg
samples/{sample_candidate_id}/record.json
samples/{sample_candidate_id}/result.json       # 存在登记结果对象时才有
```

同一候选只允许出现一种原图后缀。包内路径必须是相对路径，不能包含绝对路径、URL、父目录跳转或符号链接。压缩包时间戳固定，便于重复构建和哈希复核。

## 3. `manifest.json`

清单使用 UTF-8、按键排序、无多余空白的确定性 JSON。顶层字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `format_version` | 字符串 | 固定为 `r7-sample-export/1`。 |
| `media_policy` | 对象 | 原图允许 `image/jpeg`、`image/png`；结果允许 `application/json`。 |
| `items` | 数组 | 每个候选一条，按 `candidate_id` 排序。 |
| `exported_count` | 非负整数 | 成功写入包的候选数。 |
| `failed_count` | 非负整数 | 逐项失败的候选数。 |
| `failed_candidate_ids` | 字符串数组 | 失败候选标识，按字典序排列。 |

成功项包含：

```json
{
  "candidate_id": "<uuid>",
  "status": "EXPORTED",
  "files": [
    {"path": "samples/<uuid>/original.jpg", "sha256": "<64位小写十六进制>", "size_bytes": 123},
    {"path": "samples/<uuid>/record.json", "sha256": "<64位小写十六进制>", "size_bytes": 456}
  ]
}
```

失败项包含：

```json
{
  "candidate_id": "<uuid>",
  "status": "FAILED",
  "error_code": "OBJECT_HASH_CONFLICT",
  "error_detail_digest": "<错误摘要 SHA-256>"
}
```

失败项不会被删除，也不会被隐式重试为成功；对象存储临时故障由调度层重试并保持 `HOLD`，候选数据或完整性错误则进入清单失败项。

## 4. `record.json` 内容

成功导出的候选记录至少包括：

- 候选标识、检测时间、使用阶段和来源；
- 模型版本、流水线版本、规则版本；三者任何一个无法从登记快照或结果对象无歧义取得，候选失败；
- 系统结论、置信度和缺陷区域摘要；
- 员工反馈和管理员反馈（若有）；
- 原图与结果对象的桶、对象键、媒体类型、对象版本（若有）、登记大小和登记 SHA-256。

`result.json` 保留经校验的结果对象字节。系统只允许登记的结果媒体类型 `application/json`，并要求根对象是合法 JSON。原图和结果对象均在打包前重新读取并核对登记大小和 SHA-256；任何冲突都进入失败清单。

## 5. 包级状态和复核

| 情况 | 作业状态 | 处理要求 |
|---|---|---|
| 所有候选均成功 | `SUCCEEDED` | 可签发短时下载票据。 |
| 至少一项失败 | `FAILED` | 可下载用于人工复核，但必须先处理失败清单；不能称为完整成功。 |
| 对象存储/消息依赖临时故障 | `HOLD` 或重试中 | 不签发成功下载票据，不修改为 `SUCCEEDED`。 |
| 包或清单超过配额 | 明确失败 | 由管理员缩小候选范围或调整已批准配置。 |

外部接收方应同时保存：包文件 SHA-256、`manifest.json` SHA-256、导出作业标识、清单中的失败数量和接收时间。接收方不得依据文件名推断版本或成功状态，应以清单和业务系统作业状态为准。

## 6. 外部用途声明

交接材料应附上以下声明：

> 本样本包来自刀具缺陷检测系统的管理员手工整理结果，仅用于约定范围内的人工核对、样本分析或受控评估。包内事实不代表已批准的数据集、训练运行、模型版本或生产处置结论。任何后续使用都必须经过接收方和项目所有者的独立授权、范围核对和安全审查。

接收方不得把 `UNCONFIRMED`、`IMAGE_UNUSABLE`、失败候选或缺失版本证据的项当作可训练样本。管理员反馈与系统结论不一致时，应保留两者并记录争议，不在外部文件中覆盖原始事实。

## 7. 手工接收回执

R7 不提供外部回调、轮询、消息订阅、服务凭据或外部系统访问令牌。接收回执由管理员在受控业务系统中手工登记，或随交接材料保存。回执至少包含：

| 字段 | 说明 |
|---|---|
| `sample_export_job_id` | 对应导出作业标识。 |
| `receiver_name` | 接收组织或人员名称。 |
| `external_reference` | 外部交接单号，可选。 |
| `receipt_note` | 接收范围、失败项处理或其他说明，可选。 |
| `recorded_by` / `recorded_at` | 登记管理员和登记时间。 |

回执是不可变审计事实；更正应追加新的业务记录并说明原因，不更新或删除既有回执。回执不等同于数据集批准、训练批准或生产启用批准。

业务系统通过 `POST /api/v2/sample-exports/{export_job_id}/external-receipts` 登记回执，要求管理员权限、幂等键和已形成完整压缩包的终态作业；导出作业查询会返回已登记回执。该接口只追加业务事实，不向外部系统发起请求。

## 8. 下载与保留

下载票据为短时授权，令牌只保存哈希，原始令牌不进入业务审计正文。下载签发、下载、拒绝、过期、撤销和孤儿对象清理均应形成追加式审计事实。包、清单和票据到期后不得继续使用；发现对象引用、哈希或清单不一致时，应停止交接并进入 `HOLD`。
